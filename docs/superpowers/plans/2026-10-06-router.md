# PRD 5 Model Router Implementation Plan

> **For agentic workers:** each task below is one `agentos run`. Steps use checkbox (`- [ ]`) syntax. The tests shown must pass as written; keep the whole suite green on Windows and Linux.

**Goal:** A run never pauses while an allowed agent has quota; per-role models; a third agent (`gemini` via `agy`); a hard per-project agent allowlist.

**Architecture:** A shared quota store (`~/.agentos/quota.json`) plus a fallback loop inside `agentRunner()` in `src/orchestrator/engine.ts`. A generic read-mode guard protects planner and reviewer calls. `models` gains a `{read, write}` form. The gemini runner lands last, after a probe of the real `agy` CLI.

**Tech Stack:** TypeScript (strict, ESM, `.js` imports), vitest, zod. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-06-router-design.md`

## Global Constraints

- No new npm dependency.
- The prompt always goes to a CLI on stdin, never in argv.
- No `--dangerously-skip-permissions`, `--yolo`, `--auto` or `--dangerously-bypass-approvals-and-sandbox` for any agent, in any mode.
- Tests never touch the real `~/.agentos` (`tests/setup.ts` sets `AGENTOS_HOME`); engine tests inject an in-memory quota store.
- `dist/` is rebuilt by `orchestrator.build` (`npm run compile`) and committed.
- Existing behaviour stays the same for configs that set nothing new: `agents` defaults to the union of planner, workers and reviewer.

```ts
import { describe, it, expect } from "vitest";
import { mkdtempSync } from "node:fs";
import { tmpdir } from "node:os";
import path from "node:path";
import { fileQuota, memoryQuota, resetFrom } from "../../src/orchestrator/quota.js";

const now = new Date("2026-10-06T10:00:00Z");
const later = (min: number) => new Date(now.getTime() + min * 60_000);

describe("quota store", () => {
  for (const [name, make] of [["memory", () => memoryQuota()], ["file", () => fileQuota(mkdtempSync(path.join(tmpdir(), "quota-")))]] as const) {
    it(`${name}: marks, reads back, expires and clears`, () => {
      const q = make();
      expect(q.until("claude", now)).toBeUndefined();
      q.mark("claude", later(30));
      expect(q.until("claude", now)?.toISOString()).toBe(later(30).toISOString());
      expect(q.until("claude", later(31))).toBeUndefined();
      q.mark("codex", later(10));
      q.clear("codex");
      expect(q.until("codex", now)).toBeUndefined();
    });
  }

  it("file: two stores on the same home see each other's marks", () => {
    const home = mkdtempSync(path.join(tmpdir(), "quota-"));
    fileQuota(home).mark("codex", later(5));
    expect(fileQuota(home).until("codex", now)).toBeDefined();
  });
});

describe("resetFrom", () => {
  it("uses the wait the CLI states, else the cooldown", () => {
    expect(resetFrom("Usage limit reached. Try again in 45 minutes.", now, 60)).toEqual(later(45));
    expect(resetFrom("quota exceeded, resets in 2 hours", now, 60)).toEqual(later(120));
    expect(resetFrom("429 too many requests", now, 60)).toEqual(later(60));
  });
});
```

Existing pause tests that rely on one limited call pausing the run (for example "t9", "t10" and "cf1") keep their meaning in one of two ways:
- They become single-agent: `cfg({ planner: "claude", workers: ["claude"], reviewer: "claude", ... })`.
- Or the test returns `LIMIT` from both agents' fakes.

The first limit marks every agent in the store, so each of these tests calls `d.quota!.clear()` right before `resumeRun()`. Their other assertions stay.

Fallback authorship:
- `agentRunner` sets `RunnerResult.agent` (a new optional field in `types.ts`) to the agent that produced the result.
- The worker loop stores it as `doneBy` on the subtask's run state.
- The reviewer choice uses `doneBy ?? agent`.

Add this test:
```ts
it("picks a reviewer that did not write the code, even after a fallback", async () => {
  let reviewers: string[] = [];
  const d = deps({ plan: planOf(sub("a")), work: creates });
  d.runners.claude.write = async () => LIMIT;                     // the claude subtask is written by codex
  const codexRead = d.runners.codex.read;
  d.runners.codex.read = async (r) => { if (!r.prompt.includes("You are the planner")) reviewers.push("codex"); return codexRead(r); };
  const claudeRead = d.runners.claude.read;
  d.runners.claude.read = async (r) => { if (!r.prompt.includes("You are the planner")) reviewers.push("claude"); return claudeRead(r); };
  d.quota!.clear();
  await startRun(repo.root, "who reviews", cfg(), d, "q4");
  expect(reviewers[0]).toBe("claude");
});
```

- [ ] **Step 2: Run the tests to see them fail.** `npx vitest run tests/orchestrator/quota.test.ts tests/orchestrator/engine.test.ts`. Expect failures on the missing module and on the paused status.
- [ ] **Step 3: Implement it**, following spec §1 and §2.
  - `agentRunner` builds an order: `[agent, ...cfg.agents.filter(a => a !== agent)]`, skipping agents where `quota.until(a, now)` is set.
  - On `rateLimited`, it calls `quota.mark(a, resetFrom(res.output, now, cfg.quotaCooldownMinutes))`, logs `{type:"fallback", from:a, to:next, why:"quota"}`, and tries the next agent.
  - On error or timeout it keeps today's single fallback, to the next allowed agent.
  - When nothing is left it returns the last `rateLimited` result. If every allowed agent was **already** limited before the call, so that nothing ran, it returns the synthetic `{ ok: false, rateLimited: true, timedOut: false, output: "every allowed agent is limited until <earliest>" }` without spawning anything.
  - `pause()` sets `s.resumeAt` to the earliest `until` over `cfg.agents`.
  - The reviewer choice follows spec §2.
